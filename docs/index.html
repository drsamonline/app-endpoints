Why it exists

Every API directory is a list you read. But three questions decide whether an API is usable before you have written a line: does it need a key, can a browser call it at all (CORS), and is it HTTPS. Those are footnotes in most lists and filters here — and the filter is the product.

What it refuses to be

NotBecause
a monitorit never claims an API is up, fast, or still free today — it reports the source and the date it was fetched
a spec browserit ships the directory, not 766 MB of OpenAPI definitions; it links to the documentation
a key storeit never asks for, holds or sends an API key
a network clientthere is no fetch in it — the directory is in the page

When it goes wrong

A filter it does not know is refused with the vocabulary it accepts rather than returned as an empty list — "nothing matches" and "you typed it wrong" are different answers, and the app can tell them apart. A pin that cannot be written says it was not kept. A corrupt pin file is reported with an excerpt and a reset, never shown as "you have no pins".

Take it with you
